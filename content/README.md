# Контент сайта

Всё, что меняется чаще кода, лежит здесь в JSON. Код в `src/` только читает эти файлы:
путешествия, программы, капитаны, отзывы, лента фотоотчётов и тексты секций страницы.

```
content/
  site.json          тексты секций, навигация, контакты
  chronicle.json     лента «Фотоотчёты» на главной
  trips/<id>.json    по одному файлу на путешествие или регату
  programs/<id>.json «Путешествия» и «Гонки» (общие условия, цена «от»)
  captains/<id>.json капитаны
  reviews/<id>.json  отзывы гостей (пока пусто — секция скрыта)
```

Схемы всех файлов — в [`src/shared/content/schema.ts`](../src/shared/content/schema.ts).
Это единственный источник правды: по ним проверяется контент и из них выводятся TS-типы.

## Проверка

- `npm run check:content` — проверить все файлы, не собирая сайт.
- `npm run build` падает, если какой-то файл не проходит схему.
- `npm run dev` пишет ошибку в консоль при старте и при каждом сохранении файла в `content/`.

Сообщение об ошибке содержит путь к файлу и к полю: `content/trips/x.json: harbor.port: …`.

## Добавить путешествие

1. Положить обложку и фото в `public/photos/<id>/` (webp, без метаданных), карту нитки — в `public/routes/`.
2. Создать `content/trips/<id>.json` по образцу соседнего файла. Ключевые поля:
   - `id` — латиницей, совпадает с именем файла; используется в URL (`#trip-<id>`).
   - `order` — позиция в списке (меньше — выше). `published: false` прячет черновик с сайта.
   - `group` — `travel` или `race`: вкладка, на которой показывается карточка.
   - `harbor` — порт, координаты, сезон, вместимость: их показывает блок «Занять место на борту».
   - `routes[]` — маршруты с программой по дням; `departures[]` — даты выхода, каждая ссылается на маршрут по `routeId`. Один маршрут может использоваться несколькими датами.
   - `included[]` — необязательный список «Включено в стоимость» внутри карточки.
   - `priceNote` — короткая приписка к цене; фраза «перелёт в стоимость не входит» добавляется автоматически.
3. `npm run check:content`, затем `npm run build`.

Пути к картинкам пишутся от корня сайта (`/photos/...`), `base` подставляется в коде.

## Что остаётся в коде

Подписи интерфейса внутри карточки («Даты», «Маршрут», «Программа по дням», кнопки), названия вкладок
`Путешествия`/`Гонки` и якоря секций. Это каркас, а не контент.

## Дальше: админка

Формат выбран так, чтобы сайт можно было редактировать без правки кода:

- **Git-CMS** (например, Decap CMS) работает поверх этих же JSON-файлов: коллекции `trips`, `captains`,
  `reviews` как folder collections, `site.json` и `chronicle.json` как file collections. Правка из админки
  превращается в коммит, GitHub Actions пересобирает сайт, схема ловит ошибки до публикации.
  Нужен только OAuth-провайдер для GitHub (Netlify Identity или свой маленький прокси), бэкенда нет.
- **Своя админка** может писать те же файлы через GitHub API или держать их в базе и экспортировать в
  `content/` при публикации. Контракт один: JSON по схеме из `schema.ts`.
